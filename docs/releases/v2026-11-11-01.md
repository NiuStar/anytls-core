# AnyTLS 0.5.3 — 轮询、规则解析与运行选项开销优化

App **0.5.3**，build **0.5.3.20261111.1**，核心／发行标签 **`v2026-11-11-01`**。macOS 13+，Apple Silicon arm64 与 Intel amd64 独立原生包。

本说明冻结最终版本身份，不代表已发布、最终提交已经原生通过或附件已经可下载。Ubuntu 按用户最新范围延后（`DEFERRED_BY_USER_NOT_PASSED`）；物理 Intel 已关机，手动验收延后，不计为 PASS，不替代 GitHub-hosted Intel 原生资格。保留旧发行、历史失败和原始证据。

## 本版变化与实测范围

1. **菜单自适应轮询。** 在同一隔离 60 秒场景中，旧方案 276 次请求，新方案运行中 84 次、停止时 36 次；这是该场景的请求计数，不是实际网络、CPU 或功耗测量。
2. **规则 YAML 单次解析。** 相同规则操作边界由 2 次 YAML 解析降至 1 次，复用已校验 AST；不放宽来源、配置字节、ETag、规则集与保存校验，不重排规则。
3. **运行选项预分配。** 相同隔离样本中 leaf objects 从 403 降至 203；SDK decode/New/Close 中位耗时从 27.58 ms 降至 22.82 ms，累计分配从 18.56 MB 降至 15.51 MB。这不是 RSS；编译器分配和 SDK 阶段须分别解释，不能据此宣称所有阶段都更快或更省内存。
4. **窄化启动 YAML 解析复用（待新提交验收）。** `compile` 复用选中节点时已解析的节点列表，`stageLiveSource` 的可选热切资格判定复用同一次 YAML 语法树解码；不变更规则集／CA staging 及其独立校验。私有 Mac ARM 32 MiB 聚焦 `-race` fixture 对比为 62.67 秒→45.24 秒，私有 19/19 新旧同字节语义对照一致；这不是托管 Intel 的完整测试或任何发布资格，亦非 CPU、RSS 测量。新加入的轻量等价回归仍须由目标原生 Go 工具链执行。

以上为隔离 fixture 的实测，不是生产 TUN 启动、真实节点延迟、带宽、CPU、RSS、功耗或 live-network 性能承诺。

- **规则集启动时序修复：** 将 router 的规则初始化提前到 endpoint／inbound／service 启动之前，规则初始化完成后才开放实际入站，避免连接在初始化期间读取规则集；保留规则来源、精确来源序号校验与失败关闭。此修复不认证通用 runtime updater 并发安全。
- **私有诊断能力：** 添加默认 nil 的可选观察回调，在测试中记录固定枚举拒绝原因，不输出私有值；公开错误和 metadata 合同不变。这不是生产迁移、系统授权、OS／launchd 启动或所有历史超时的修复。
- **流关闭竞态修复：** 对固定 `sing-anytls v0.0.11` 的私有认证补丁，在新流发布给 Session 前安装客户端关闭回调，消除 `CreateStream` 与会话关闭对 `dieHook` 的并发读写；保留原 ACK 补丁、公开 `OpenStream` 入口和失败关闭。原 main Intel race run `43002628520` 的失败证据仍为 FAIL，修复后的托管双 Mac 全量 race 须按后继提交重新验收。
- **继承 0.5.2 语义：** 启动完成仍为 `LOCAL_READY / INTERNET_UNVERIFIED`，不等于外网可用或节点认证；热切仅作用于受支持的预构建节点，新连接用新出口，已有连接保留。配置／能力不匹配返回 `RELOAD_REQUIRED`，不隐式 stop/start。UNKNOWN 只凭原操作绑定的认证只读证据恢复，不因刷新或版本更新解锁，不重放旧操作。
