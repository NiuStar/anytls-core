# v2026-10-22-04 — 启动失败的分阶段诊断

## 变更

- 手动启动、手动重载及保存自动应用失败，展示受控阶段、原因码、独立恢复／清理／回执状态与有限检查建议；不再仅显示笼统的“检查 VPN 状态和连接配置”。
- 生命周期在实际证据产生处记录状态：未执行、无法确认、核验失败及核验通过分别表达；主错误不被回滚或诊断保存错误覆盖。返回固定枚举，不向网页发送工具原文、路径、节点密码或订阅地址。
- 修复重载停止步骤因回执写入失败而退出、尚未执行启动却误报整次成功的问题；保留保存成功但应用失败的 pending 状态，不增加额外启动／恢复操作。
- 重试观察在实际重读前置为未知，成功后使用当前作业／TUN 观察；不沿用已失效的 RUNNING／TUN。原 HTTPS 目标、重试条件、次数、期限和 TLS 策略保持不变。
- 前端拒绝不合法诊断组合，不能采信其恢复结论；合法“结果未知”仍明确显示未知。保留配置方案、节点测速和原保存契约。

## 安装与兼容

```bash
curl -fsS https://raw.githubusercontent.com/NiuStar/anytls-core/main/get.sh | bash
```

请在 Mac 本机普通用户终端执行，不加 sudo。公开安装器默认取最新稳定 Release；本说明存在不代表该版本附件已经发布。

详细诊断需要新版程序和新版受限助手共同提供。新客户端兼容旧助手的无诊断响应，只能显示“助手未提供详细原因；可能为旧版助手”，不能从旧的 START_FAILED 推断具体原因。更新已安装 root 助手仍需用户在本机走既有授权安装流程；HTTP 不安装或重启助手。旧客户端对新助手新增响应字段不承诺兼容，应配套更新。

安装保留配置、选择与应用密码，备份旧程序，核验后切换 WebUI，但不启动、停止或重载 VPN。本轮开发与验收没有安装正式助手或控制正式 VPN。

## 发布门与限制

- 以上是修复候选的证据，不替代最终 clean 提交的构建与包验证。最终产物须绑定真实 vcs.revision、vcs.modified=false、wrapper END、包内二进制和对应源码 BUILD-IDENTITY。双架构发布作业、独立 CI 和公开附件下载核验分别裁定。
- 生命周期系统动作使用 UNIT-SIMULATED seam；真实 IPC／HTTP 不等于已安装助手、特权 TUN 或生产路由／DNS 恢复验收。
- 诊断改进不等于已查明此前用户那次启动失败根因，也不声称已修复未知的节点、证书、路由或网络问题。旧历史 service-diagnostic.json 无请求关联且不可信，不能冒充本次操作结果；没有新增任意特权文件／日志 HTTP 接口。
- 旧版03的独立标签 CI Intel 失败仍保留为历史未定位事项，不能由新版本通过倒改旧结论。
- SHA256SUMS 依赖 GitHub HTTPS，不是独立真实性签名；无 Apple 签名或公证。
