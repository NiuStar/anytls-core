# v2026-11-06-01：修正 TUN 与 DNS 的初始地址族策略

## 变更

- TUN 默认使用 IPv4-only：不再无条件配置虚拟 IPv6 地址，DNS 同时采用 IPv4-only 策略，避免 IPv4-only 节点收到无法出站的 IPv6 目标连接。
- 顶层 YAML `ipv6: true` 显式启用双栈；未配置或 `ipv6: false` 使用 IPv4-only。该字段必须是布尔值，拒绝 null、字符串、数字及 `off` 等非法值。
- Clash 配置导入、转换与导出保留显式 `ipv6: false`；CLI、WebUI 与助手共用的配置编译入口遵循相同策略。
- 显式双栈仍需节点具备真实 IPv6 出口。节点服务器地址的地址族不代表远端出站能力；本版不自动探测该能力。
- 不修改严格 TLS/DoH 校验、节点选择、AnyTLS 协议、SDK 权威边界或失败后重试；不是 Google 专用规则或失败后的 IPv4 回退。

## 兼容与安装

**默认行为有意调整。** 旧配置若未写 `ipv6`，更新后 TUN 将采用 IPv4-only；需要且具备双栈出口的用户应显式设置 `ipv6: true`。代理模式保持原输出策略。本版不为服务器增加 IPv6 地址、路由或隧道，也不修改 Chrome、系统 DNS 或 QUIC 设置。

公开发行验收完成后，在 Mac 本机以普通用户执行（不要给整条命令加 sudo）：

```sh
curl -fsS https://raw.githubusercontent.com/NiuStar/anytls-core/main/get.sh | bash
```

保留现有节点、配置与应用密码。完整安装按已有安装器策略更新助手及 WebUI：原 VPN 运行时安装成功后默认单次重连，原 VPN 停止时不自动启动；UNKNOWN/pending 不通过盲重试解除。下载 HTTPS、系统 CA、节点已有 CA/pin 与目标网站 TLS 校验不放宽。

## 验证与边界

- 冻结功能候选已通过 Linux 标准内嵌全套测试、独立审查及 Mac arm64 隔离原生测试、构建、CLI 检查。默认/false 的实际 SDK 测试验证 AAAA 为 NOERROR/NODATA、零上游 AAAA、零 IPv6 业务 CONNECT；真实环回 AnyTLS HTTPS 仅一次 IPv4 业务连接。
- 最终发布还要求精确发行提交的 branch/main/tag 三平台 CI、原生双架构发布构建、五份归档与 SHA256SUMS 公开读回校验。该说明不是这些门禁的成功回执。

- 程序尚无 Apple 签名/公证；不承诺第三方节点、全部网站或长期稳定性已经验收。
