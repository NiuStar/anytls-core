# v2026-11-05-01：启动节点与默认出口联动

## 变更

- 在节点卡片选择一次，即同步最终 `MATCH` 所指向的直接 select 组及实际启动节点；反向从该默认组选择具体节点，也同步启动选择。
- 不覆盖 OpenAI、地区等专用分组，不拍平嵌套策略，不自动给分组插入节点，不改写显式 `MATCH,DIRECT` 或 `MATCH,<具体节点>`。
- 已有方案若启动/DNS 节点和业务默认组失配，分别显示实际身份，允许一次明确点击同步；不静默迁移历史方案。
- 保存复用方案事务的捕获、CAS、备份、读回、错误回滚；前端提交原页面 ETag，并阻止旧页面、旧会话的迟到操作污染新状态。
- 包含当前 main 已发布安装脚本兼容修复：完整安装默认更新助手和 WebUI，只对原运行 VPN 执行一次重连，停止状态不启动；支持 `--no-reload-core`，合法托管 WebUI 与 macOS 负系统 UID。
- 发布流程在任何 Release 写入前要求同标签、同提交的三平台 CI 全部成功，避免独立发布工作流绕过失败的 tag CI。

## 安装与生效

发布验收完成后，在 Mac 本机以普通用户执行（不要给整条命令加 sudo）：

```sh
curl -fsS https://raw.githubusercontent.com/NiuStar/anytls-core/main/get.sh | bash
```

- 保留现有配置、节点、应用密码；本机系统授权阶段更新受限助手。
- 原 VPN 运行时，完整安装成功后默认重连；原 VPN 停止时不自动启动。
- 普通 WebUI/CLI update 仅更新用户程序，不替换 root 助手。
- UNKNOWN/pending 必须先只读核对，不能通过重复安装获得回执。
- `skip-cert-verify` 不等于已授权新操作；安装器不会自动继承旧 `-allow-insecure`。本版不关闭发行下载 HTTPS 校验或系统 CA 校验。

本文件是冻结候选的发布前说明，不是发布成功回执。最终审核、原生构建/测试、分支/main/tag CI、公开五份归档与 SHA256SUMS、下载程序 version 验证将另存绑定精确提交及 tag OID 的收据，不能以本说明替代。

联动范围是 WebUI。CLI 独立选择路径不在新增双文件事务范围；现有乐观多文件事务不承诺断电/崩溃原子性或系统级写锁。详见[联动契约](../startup-node-link.md)。
