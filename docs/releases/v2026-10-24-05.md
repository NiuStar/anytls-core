# v2026-10-24-05 — 服务器整叶证书指纹

## 变化

- Clash／原生 YAML `fingerprint` 定义为服务器叶证书 DER 的 SHA-256，使用64位十六进制；与 `client-fingerprint`（ClientHello）和 Base64 SPKI 公钥 pin 分开。
- 指纹贯穿配置转换、导入、追加、表单编辑和运行编译；Go TLS、SDK uTLS、Chrome155 实际握手均校验 `rawCerts[0]`，错误指纹在发送 AnyTLS 认证前拒绝。
- 显式空、null、非字符串、畸形指纹，以及与 CA、SPKI 或开启跳验混用均拒绝。不支持的 native engine、Reality、ECH 组合明确失败，不忽略指纹。
- 保持 Go 1.27.3、sing-box 1.14.3 和既有三套认证补丁；追加独立叶证书补丁、构建回执及对应源码材料。

```yaml
fingerprint: "676e4eab998ebcdfc0bb499b68c0cae73861485ef8aad1712be62b7bc8f02948"
client-fingerprint: "chrome"
skip-cert-verify: false
```

上例指纹仅用于说明字段，必须替换为通过可信渠道取得的目标服务器叶证书指纹。不得从未认证远端自动抓证书后直接信任。pin-only 接受指纹匹配的自签名证书，不承诺 PKIX 链、主机名或有效期验证；叶证书重新签发即使公钥不变也需要更新指纹。

## 下载与边界

提供 macOS arm64／amd64 预编译包、应用源码、各架构对应源码及 SHA256SUMS。默认安装只下载校验和与本机架构程序包，无需本地 Go：

```sh
curl -fsS https://raw.githubusercontent.com/NiuStar/anytls-core/main/get.sh | bash
```

- 本次发行不自动替换生产程序、特权助手或正在运行的 VPN；生产切换另行备份和授权。
- Intel 原生 CI 与用户目标机体验分开，不宣称修复此前 START_FAILED 或 DIRECT 问题。
- Chrome 首 Hello 匹配不等于完整浏览器流量等价；没有本次真实 ML-DSA 证书链握手验收。
- 原有路由、私有订阅、仅二进制更新、连接记录覆盖缺口及 CLOSED 保守终态不变。无 Apple 签名或公证；SHA256SUMS 是传输完整性校验，不是独立签名。
