# v2026-11-08-03 — AnyTLS 0.4.4

App `0.4.4`，build `0.4.4.20261108.1`，macOS 13+。Apple Silicon arm64 与 Intel amd64 分包；核心与固定助手能力内嵌，组件安装不另从 GitHub 下载。

## 修复范围与完成门

本版处理组件迁移中旧助手 STOP 回执与新检查契约不兼容的问题，并为既有未完成更新提供独立、显式的恢复流程。源码实现、隔离原生验证、精确提交审查、原始分支/main/tag CI 和公开附件下载均须通过；本说明不提前声明这些门已通过。

- 仅在实际已停止且快照目录明确不存在的生命周期分支，结构化恢复字段记为 `NOT_ATTEMPTED`；旧的人类可读 `UNAVAILABLE_NO_BASELINE` 保留，不声称路由／DNS 已验证恢复。
- 迁移使用独立的 32 位十六进制助手操作 ID，与 64 位迁移 ID 分开。STOP 前持久化操作绑定；STOP 响应与精确操作时间线按规范化类型 JSON 保存并链接摘要，不将其误称原始网络字节哈希。
- 不全局放行 `UNKNOWN`。已审计旧助手的无基线兼容分支必须具有匹配的助手映像、版本、操作、epoch、配置身份及完整闭合的助手事件流。缺失、丢失、不匹配、恢复或清理失败仍保持 HOLD。
- 历史未绑定的 `UNKNOWN` 不能靠当前停止状态或相近时间改判成功，也不能靠删除记录解除。显式恢复的新事务必须保留旧记录、旧暂存映像与未知结果，使用新操作进行独立 STOP，再经本机系统授权完成更新。

## 受影响用户的恢复入口

针对先前显示「迁移 STOP／暂存结果未知」的规范安装，使用新 App 的独立「恢复未完成的组件更新…」入口。确认文案须说明这是一个新的停止／更新事务，可能中断网络，不代表上次操作成功。不要重复点击普通安装，不删除 `.desktop-migration-*` 记录。

恢复只有在旧证据、当前核心／助手／配置及控制台身份可验证、没有其他未决操作时才可执行。取消确认不发送 STOP。丢失响应、超时或持久化不确定后不自动重试；刷新／重启 App 不重发 STOP 或管理员授权。更新不自动启动 VPN。
