# v2026-10-27-04 — 异常后 stop/start 恢复解锁

## 行为变更

修复 `anytls stop` 已卸载服务，却因 `restoration_failed; snapshot retained` 返回失败，继而 `start` 又因 `SNAPSHOT_EXISTS` 拒绝的循环。

- 服务已确认未加载、未运行：DNS／公共路由／节点路由与启动前不一致、baseline 缺失或损坏、网络探测异常，均单独记录 FAILED／UNKNOWN 恢复警告，不再当作服务仍在运行。
- 为保留诊断，旧活动快照移动到同父目录随机命名的私有 `.service-recovery-*` 归档。安全的历史遗留快照也可在 START 时自动归档；不要求用户删除快照或另加 force 参数。
- 已运行或状态不明的服务、目录身份替换／symlink／不安全 owner 或权限、归档 I/O 失败仍拒绝覆盖。正常清理与归档共用身份检查；保留失败启动的主错误及回滚原因链。
- 成功的 helper、旧／新 IPC、认证 HTTP、手动控制和保存自动应用均保留恢复警告；页面等待期间切换会话或替换操作，旧提示不会覆盖新提示。
- 不改 TLS 信任、节点、路由规则、DNS 政策、就绪预算或重试次数。不宣称网络已恢复，也不宣称修复原 Intel `TUN_NOT_READY` 的未知根因。

## 更新与使用

正式发布完成后，在 Mac 本机终端运行默认最新版安装入口（不要加 sudo）：

```bash
curl -fsS https://raw.githubusercontent.com/NiuStar/anytls-core/main/get.sh | bash
```

安装器保留配置、选择和密码，备份旧程序，并通过本机标准系统授权安装配套助手；不保存系统密码，不自动停止或重载 VPN。普通 `anytls update`／网页程序更新不替换 root helper，因此仅更新普通程序不足以让旧助手采用新停止逻辑。

更新完成后检查 `anytls version` 与 `anytls helper status`，再按自己的维护安排执行 `anytls stop`、`anytls start`。恢复警告仍需留意，但不再因历史恢复差异而永久卡住启动。

本次授权仅公开发布 macOS ARM64／Intel，不远程安装、不更新现有助手、不切换 WebUI、不停启 VPN；Intel 原生用户体验另测。保持既定 Ubuntu＋Mac ARM64／Intel CI、二进制发行流程、Go1.27.3／SDK／依赖／补丁／wrapper／打包器／安装器不变。校验和是下载完整性证据，不是 Apple 签名或公证。
