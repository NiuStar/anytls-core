# v2026-10-25-01 — 显式 SNI 控制与严格信任

## 修复

节点支持 `disable-sni: true`，仅省略线上 ClientHello 的 server_name 扩展。节点的显式 `sni` 仍作为 CA 模式的主机名验证参考，不因此关闭 CA 链、主机名或整叶指纹验证。省略／false 保持旧行为；显式 null、字符串和非布尔值失败关闭。转换、导入、保存、导出及实际运行保留该字段。详情见 [选项说明](../disable-sni.md)。

```yaml
# 在既有可信节点中按需增加；保留原 server、port、password 和 fingerprint。
disable-sni: true
```

`fingerprint` 继续表示完整服务器叶证书 DER 的 SHA-256，不是 SPKI 或 ClientHello 指纹。pin-only 不执行 PKIX 链、主机名或有效期验证，但必须精确匹配受信任渠道取得的指纹；错误 pin 在 AnyTLS 认证之前拒绝。禁止与 skip-cert-verify: true 混用。

同时纳入之前未公开发行的有限容错：仅认证之前 TLS 拨号的明确 ECONNRESET 最多尝试三次，退避150／300毫秒、共用原拨号总期限。每次重新执行相同严格验证；证书／认证／取消错误不重试，认证和业务不重放。它是有限缓解，不是网络根因修复。

保留 main 已有的 LAN WebUI 安装器识别／规范地址修复、原有路由和策略组语义。依赖、工具链及认证 SDK 补丁链不变：Go1.27.3、sing-box1.14.3；最终二进制与对应源码重新按本版本提交构建。

## 面板联动与既有配置

面板的配套修复独立发布：已确认安装证书的托管公网 IP 严格整叶 pin 输出不再因为签发域名而自动填入域名 SNI；证书签发身份和用户显式外部 SNI 保留。客户端不会静默删除现有配置的 SNI，也不会自动修改生产配置。未更新面板或旧订阅仍可能带原 SNI，需要用户在理解影响后显式选择本选项。
