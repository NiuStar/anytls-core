# v2026-10-26-02 — 连接记录可信 sticky 祖先兼容修复

## 修复范围

连接记录文件守卫此前拒绝所有 sticky 位。目标 Mac 的 root 拥有的 `/Library/PrivilegedHelperTools` 实际为01755，现有守卫在创建记录根之前就拒绝该祖先。本版仅允许可信、非 group/world 可写的**非私有目录祖先**带 sticky 位，不修改任何系统目录权限。

- 私有记录根、namespace、instance 仍必须为0700；普通文件仍必须为0600、单链接、无特殊位。
- group/world 可写祖先（包括01777）、setuid／setgid、错误 owner、symlink 仍拒绝；生产存储仍要求 root owner。
- 不修改路由、节点信任、TLS、记录终态合同、SDK、Go版本、依赖、构建包装器或打包器。不包含仍独立且未合并的Windows／Linux移植，也无这些平台附件。

## 未关闭边界

- 已证明并移除一个记录初始化前置障碍，**尚未运行正式 root 存储写者、已安装助手记录IPC或正式TUN恢复验收**，不能声称所有记录已完整恢复。所有其他可能的 root 初始化错误尚未穷尽排除。
- 用户配置与 staged 配置已观察到相同摘要；这不证明当前进程的全部运行状态。约四万条规则归属 UNKNOWN 是独立问题，本版不修复、不隐藏。
- 不宣称 DIRECT 域名／IP白名单出口投诉、Intel START_FAILED、全部间歇启动失败、IPv6／DNS或长期稳定性已解决。ROUTED 不等于连接成功，DNS／REJECT／早失败仍有覆盖缺口；CLOSED 仅为最后保存的停止状态，完整收尾未验证、连续性 UNKNOWN。

## 安装与生效

普通用户在 Mac 本机终端使用稳定预编译入口，不加sudo：

```sh
curl -fsS https://raw.githubusercontent.com/NiuStar/anytls-core/main/get.sh | bash
```

原始入口失败时的同仓库官方 API 入口见 README。默认仅下载校验和与所选架构程序包，不要求Go；精确应用源码、双架构对应源码和许可材料另在Release提供。摘要不是Apple签名或公证。

**发布本身不安装、不更新或重启生产程序、WebUI、助手或VPN，不更改网络及系统目录权限。** 用户完整安装涉及本机授权和WebUI切换，VPN不自动reload；磁盘程序更新不代表正在运行的核心已加载本修复。正式 root 写者和记录IPC需要匹配程序／助手及用户另行显式启动后的现场验收。
