# AnyTLS App 0.5.4 / build 0.5.4.20261112.1

核心与预定标签：`v2026-11-12-01`。面向 macOS 13+，Apple Silicon arm64 与 Intel x86_64（发行名 amd64）分别提供原生包。本文是最终提交的发布说明来源；冻结时发布、最终 CI 与附件资格尚待完成，不能仅凭本文认定附件已发布。

## 启动不再逐节点检查

- START 与需要重新启动核心的 RELOAD 不再遍历节点查询路由，也不等待节点 TCP、TLS 或 HTTPS 检测。全部配置节点仍保留，不按当下网络可达性裁剪；静态规则出口、warm 节点、host exclusions 与自动物理接口策略保持。
- 完成表示 `LOCAL_READY / INTERNET_UNVERIFIED`：本地核心进程、同一 TUN、DNS、配置编译及 TLS 策略、回执写入仍须通过；不是互联网可用承诺。节点自身的连接 TLS 校验、显式风险确认、回滚及失败关闭没有被删除。
- 新 baseline v2 的恢复范围为 `LOCAL_INTERFACE_DNS`，只保存公共物理接口与原始 DNS，不把未检查的节点路由写成已验证。磁盘诊断 schema 3 明确 `node_route_verification=NOT_RUN`。旧 v0/v1 baseline 的 STOP 恢复继续按其原节点路由范围核验，不借新范围追认旧操作。
- 链路失败只建议用户切换节点；若仍失败，检查本地网络。不自动切节点、不自动重启、不将未知结果改为成功。

## Focus 测试入口修复的边界

Focus fixture 使用同步 MainActor 入口拥有 run loop，异步测试完成后写入退出结果并以 `CFRunLoopStop` 唤醒入口。只修复测试入口的完成所有权，生产 App 的焦点行为不因该入口修改。最终入口在 ARM 上实际执行 128 条检查通过；五套 Swift 源清单共 1180 条，不等于最终 0.5.4 双架构全部执行通过。历史 Focus 429 超时的根因仍未证实，不由这次窄修复反推为已查明。

Mac Studio ARM 上此前部署的工程候选执行过一次真实 START，本地就绪成功：HTTP 200、`LOCAL_READY / INTERNET_UNVERIFIED`、运行中核心与新 TUN 读回一致。该次操作时间线为 11.103836 秒；不是通用启动耗时承诺，也不是最终 0.5.4 附件性能测试。配置与节点选择哈希前后相同，126 个 helper 事件完整保留，未记录节点／server-route 或 HTTPS 检测阶段。

该工程候选仍带旧核心版本字符串，不是本次新身份的发行附件。root 私有 baseline／磁盘诊断和 root 快照文件未能直接读回，仍为 `UNAVAILABLE`；聚合 trace 有 gap，核心快照缺少 terminal。完整 helper／Web 终态及运行 PID／TUN 的可见验证，不等于这些缺失证据已补齐。未测试互联网连通性，也未测试原物理 Intel／IPv6 缺失场景。VPN 已留在运行状态，本轮发布准备不连接或操作该机器，不重装、不重启、不停止它。
