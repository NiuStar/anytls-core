# v2026-10-24-03

## 功能

与 `NiuStar/anytls-go` v0.0.28 的无域名公网 IP 私有订阅联动。服务端持久证书和独立令牌，客户端先认证订阅 TLS 叶证书，再读取带 SPKI 公钥认证的节点。

WebUI 在“配置与规则 → HTTPS 订阅”提供独立的“从此订阅仅添加节点”入口：预览新增数量，明确确认后备份并追加。保留现有节点、选择、策略组、规则和已保存订阅；同名不同内容整次拒绝，相同内容为 no-op，不擅自切换出口。不存储该添加链接为自动刷新来源。

本版还把 main 的二进制-only安装策略纳入 CLI／网页内嵌更新器：默认仅 SHA256SUMS 和对应架构二进制包，保留包内许可证；源码与完整对应源码仍提供手动获取。

## 信任模型

- URL fragment：整张实际叶证书 DER 的 SHA-256，小写 hex，握手检查正确后才发送访问令牌。不走 DNS、环境代理或跳转，只接受公网数字 IP。
- 节点字段 `certificate-public-key-sha256`：同证书 DER-SPKI 的 SHA-256，canonical 标准 Base64，拒绝与 CA／skip-cert-verify:true 混用。
- 明确为 pin-only身份认证，不宣称额外验证公共 CA、域名或有效期。完整链接是秘密信任交接；攻击者替换整条链接就能替换信任根。证书变更需重新可信分发。

## 验证边界

原候选完成 Mac 原生完整测试、vet、双方二进制构建和 std／Chrome uTLS 六个真实 TCP 正负例；错误指纹／密码均无目标连接或载荷。固定旧版测试证明信任功能缺失的业务 RED。

独立复审发现服务端重装 env 作为 Shell 执行及非规范端口问题；已改用 Go parser／进程内 config run，新增实际密码特殊字符与端口 RED→GREEN，修复后独立窄复审通过。最终源码构建、CI 和公开附件须按实际发布回执核对，不以这些候选描述替代。

浏览器桌面／手机验证使用禁用服务控制的隔离真实后端；仅远程URL输入转换为本地 YAML 的测试适配明确披露，不把它称作公网订阅验收。原生跨项目订阅测试另验证真实服务端 HTTPS 内容→固定证书获取→解析→认证追加保存。
