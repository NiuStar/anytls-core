## 新增入口与规则顺序

在 **配置页 → 分流规则 → 新增规则** 选择规则并查看预览，再点 **校验并保存**：

- 类型、目标、插入位置使用下拉。支持 `DOMAIN`、`DOMAIN-SUFFIX`、`IP-CIDR`、`GEOIP` 和现有有效 `RULE-SET`；不提供新增 `MATCH`。
- `GEOIP` 国家代码为下拉，目前只有精确 `CN`；`RULE-SET` 标签从当前配置已有且通过校验的本地规则集中下拉选择。DOMAIN／DOMAIN-SUFFIX／IP-CIDR 的匹配值仍为文本输入，不伪装成已有集合；指定序号为数字输入，`no-resolve` 为复选框，仅适用于 GEOIP／RULE-SET。
- 默认在最终唯一 `MATCH` 前插入，也可选最前面或现有第 N 条前，界面从1编号。不新增／移动 MATCH，不重排已有规则；**已有前序规则仍优先**，新增规则不保证会命中。
- 目标含 DIRECT／REJECT，以及当前可解析到有效出口且可构造的节点／策略组；不接受任意未配置目标。

规则集不仅检查路径、SHA-256 与 JSON 结构，还通过实际内嵌核心的 decode/New/Close 校验，不调用 Start、不启动监听。列表排除原生无效规则集；提交时重新校验新引用和已有启用规则集。即使 SHA 正确，非法 CIDR、正则或未知 SDK 字段也不能被该入口保存激活。没有有效标签时不能提交 RULE-SET，不自动创建、下载或转换远程 provider；这不是对全部配置入口扩大校验政策。

## 保存、并发与安全拒绝

- 规则列表、选项和 ETag 捕获自同一份配置字节。提交必须携带精确 `If-Match`：缺失返回428，配置已改变返回412；写入前再次检查原字节，避免陈旧页面覆盖新配置。保留登录、同源 Origin、CSRF、动作锁、原子写入及读回校验。
- 已存在相同类型／匹配值／目标／标志的规则时，不重复插入、不写文件、不重连；既有规则 token 周围允许的空白按现有比较方式处理，不放宽 GEOIP 必须精确 CN 的原生语法。
- 只在支持的显式块状 `rules` 列表中插入一条带引号的规则，不做 YAML 全量往返。选择、订阅、其他规则、注释、未知字段及标量拼写保持原字节。缺少末尾唯一 MATCH、流式列表、规则锚点／别名、顶层合并或多行规则等不支持布局返回 `RULE_EDIT_UNSUPPORTED`，保留原文件，提示使用原始编辑器；不宣称任意 YAML 均可无损编辑。
- 沿用既有保存／应用分离合同：内容改变且 VPN 正在运行时尝试受控 reload，可能短暂断网；停止时仅保存，不启动 VPN。应用失败不冒充保存失败，磁盘保存成功也不等于已生效；未知服务状态保留独立提示。
- 保存期间锁定输入；配置方案切换、退出登录与陈旧请求不能回填旧表单或保存反馈。已保存结果不因随后规则列表／状态刷新失败而消失。原始配置草稿保留，但旧保存版本失效；须先复制草稿，再重新读取并合并。
- 建议编辑前导出配置或保存为方案；此入口不自动创建导入备份。接口细节见 [API 合同](../../web_assets/API.md#single-rule-add-contract)。
