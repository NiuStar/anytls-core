# 安装器终端授权提示修复

## 用户反馈与已知边界

用户报告：下载和校验已通过，安装受限助手阶段连续等待约220秒，直到Ctrl+C才出现密码提示。本问题不能被归因为用户未输入密码；上传文本的Password位置不能替代用户对实际显示时序的说明。尚未在用户机器复现完全相同的显示／sudo时序，不声称已证实唯一根因。

旧Python安装器只把helper stdin接到只读/dev/tty，stdout/stderr继承外层终端；授权同时存在5秒后台进度线程，反复写stderr。这会干扰交互提示的可见性。新流程不读取或保存密码，使用同一个r+b无缓冲/dev/tty作为sudo与helper的stdin/stdout/stderr。

## 新流程

- 已验包且保留分发材料后，清楚打印进入系统授权阶段。
- 授权及helper install期间不启动heartbeat。
- 先由绝对路径`/usr/bin/sudo -v`执行标准本机授权，然后调用已验候选的`helper install`；sudo按本机策略可能再次提示，三个流仍直接接到终端。
- 授权拒绝时明确提示未继续助手安装／程序替换；旧程序保持不变。原有首次示例配置／PATH link可能已经准备，不将整个安装过程冒称全事务。
- 完成后继续原有助手认证status、程序备份／原子替换与安全WebUI切换，不停止或重载VPN。
- 不新增sudoers、askpass、密码输入字段、密码代理或额外root命令；不保证绕过本机sudo策略、TTY/PAM或硬件认证要求。

## 已执行验证

新增回归绑定旧安装器，授权heartbeat禁用断言真实失败；新版全工具105测试通过，授权拒绝验证未安装helper、未替换旧程序、未重启WebUI且清理候选。三个既有命令序列断言按新增sudo-v更新，保留完整版本／helper／发布顺序检查。

Mac Python3.9三套工具回归通过。Mac真实pty.fork控制终端下，以printf管道启动bash/Python，再以同一/dev/tty三流交给无特权合成child：先见测试prompt，再发送非秘密marker，child确认并退出、父wait。未运行sudo、未使用密码、未执行产品、未操作真实服务；这只验证终端交接，不等于用户机器密码授权已修复。
