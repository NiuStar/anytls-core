# AnyTLS 系统优化方案与实施计划

## 1. 范围与基线

用户要求：依据推荐顺序形成方案和计划并实施。开发基线为 `f67929ea809c530d12e6ea1ad90b8f135c108c2a`，继承已验的单条删除和规则导航候选；这不是当前公开版或已部署版。

本轮以同功能等价优化为主，按 P0→P1→P2→P3→P4→P5 逐门推进。测量、实现、独立审查、公开发布、安装及真实 TUN 切换分别验收。此次不修改正式配置，不安装、不更新助手、不停启 VPN；不操作 Intel 故障机。最终是否解决 Intel 现场问题保持另测。

保留 AnyTLS、TCP/UDP、TUN/mixed、DNS、Chrome 指纹、严格证书验证、规则原序、记录权限/所有权与恢复语义。不通过默认关记录、减少历史、删规则或关闭安全校验制造提速。保留已取消的历史容量门状态，仍记录实际空间并对真实 I/O、超时和身份异常失败关闭，不自动删除任何历史证据。

## 2. 衡量口径

- 启动：配置编译、SDK decode/New、manifest digest/完整 codec、记录初始化与绑定各阶段；微基准不外推整体 TUN 就绪。
- 运行：私有记录写者的发布次数、write/Sync 次数、完整读回、高水位/丢失/时效。记录回调仍无同步文件 I/O。
- 管理：只读规则清单和有效新增选项的工作量、响应完整性、配置/ETag绑定及保存/应用回归。
- 内存：Go B/op、allocs/op 属于累计分配；如采 RSS，注明采样范围和峰值不是 OS high-water。不得从文件大小推断内存改善。
- 转发：复用严格 TLS AnyTLS 和 TCP/UDP 回环正负例，核错误认证零业务、取消/回收及记录归属；本轮无公网链路吞吐承诺。
- 体积：程序逻辑字节、固定 gzip 下载量、Mach-O 段、实际链接依赖分别计量；源码包/许可证/工具链、安装备份单列，不删除必要材料。

固定 Go1.27.3、四个正式 build tags、CGO0、GOMAXPROCS=2、同 ARM64 Mac 和缓存条件，旧/新数据使用相同生成器/seed和输入SHA。比较使用交错 fresh-process 复本，保留所有原值；以实际差异与噪声判定，不预设50%收益。没有可重复收益的候选不以“性能优化已成功”合入。

## 3. 执行阶段

### P0 — 冻结基线与测量入口

建立独立源码/证据和普通用户 Mac 私有目录，记录程序/助手/核心的当前 PID/start/argv、文件摘要、DNS/proxy/route；不读取或修改 root-private 内容。保存基线完整源码清单、规范 tags/锁/补丁身份。准备可在旧代码运行的等价 oracle 与分项计量，先实跑基线。

### P1 — 启动及分配开销

首个最小候选：`ManifestDigest` 已完整 `Validate(Manifest)` 后，避免对同一固定投影重复语义校验；仍用原 bounded encoder、字段顺序、转义、预算与摘要算法。保留所有跨消费者 digest校验、完整严格 codec 所有权副本、Box真实对象绑定和失败降级。

门：原旧函数 test-only oracle；有效/无效结构、budget L/L-1/0、错误优先级、Unicode/转义、输入不变、完整摘要字节等价；同输入旧/新微基准与完整关联回归。此优化不得描述为60秒窗口修复或 Intel已恢复。进一步 codec 元数据缓存、typed clone只在 profile支持时另案，不本轮盲改。

### P2 — 记录发布/I/O

先测定时 flush tick 的实际调用链。优先消除同一个 tick 中 `commit` 已发布后立即再次 publish 的重复状态写入；空闲 tick 的必要心跳、损失/来源状态、完整批处理、Sync顺序、失败不重试、终态保守投影均保留。不得简单取消空闲心跳造成 FRESH过期。

门：相同新测试先在旧版证明重复发布，再在候选减少；私有真 writer/readPage完整数据一致，保留所有 I/O/关闭故障及不确定性回归。用真实写/Sync计数而非主观耗时声明减少。

### P3 — 配置管理操作

增加向后兼容的显式 list-only 读取模式：仅列表不构造节点选项或校验外部规则集；默认旧GET及新增表单选项保留完整有效性校验。浏览列表采用 list-only，新增表单读取完整选项；分别绑定捕获配置和ETag，迟到旧响应不得混入表单。新增/删除保存仍执行完整候选与剩余激活规则集校验。

补齐固定错误码中文映射（写入失败/读回未确认），不承诺错误后原文件一定没变，不自动重试。单条删除的逐行 YAML parser 热点先量测；若没有保持物理行证明的窄改方案，明确保留为后继，不在本批替换解析器或放宽检查。

门：真实认证HTTP旧GET兼容、list-only工作量见证、无效规则集options仍排除、ETag/配置变更及保存链；前端VM与桌面/手机实际浏览器回归。

### P4 — 核心与分发体积

对基线/最终同条件构建做文件、固定gzip及Mach-O段/链接模块归因。已存在的最小registry、debug/cache裁剪不得重复记为新收益。优先找保持功能的真实冗余；仅go.mod声明不作可删除证据。不改gVisor/TLS后端、不拆控制程序/核心，除非另有明确方案和兼容证据。

本阶段允许结论为“本批未证实可安全进一步裁剪”，交付可复核体积基线与候选排序；这不是漏做，也不能编造减量比例。对应源码包减量须保留许可和可重建性，不能仅删测试/工具链后发布。

### P5 — 集成与交付

最终冻结候选，独立复核受影响代码，原生格式化、完整test/vet/clean build和精确VCS身份，回环协议与记录回归，认证HTTP/实际浏览器，前后生产保护和独立读回。输出每阶段：原值/候选值、等价证据、剩余限制、完整源码/产物SHA。

新公开版本和生产切换不包含在本次实施完成中；用户另行授权发布后，再完成发行CI与公开附件审计。

## 4. 暂不实施的高风险路线

- 换TUN栈、删gVisor、去Chrome指纹、改变证书信任或TLS重试。
- 深度分叉SDK、全局缓存可变manifest、浅拷贝代替独占所有权。
- 取消记录心跳、改变历史保留/终态信任/断电语义。
- 自动规则去重、合并、重排、扩大中国IP规则或改真实出口。
- 未经测量的Go GC调参、频繁强制GC、UPX或删除供应链必要材料。

## 5. 完成条件

P0基线实际执行，P1/P2/P3各有行为/等价/工作量证据，P4有实际体积归因与明确裁剪裁定，P5最终候选原生全套和受影响交互/独立审查通过。每项未执行或不可覆盖的生产/Intel指标必须写明；不得把部分完成称作整个系统优化完成。
