# DNS runtime evidence, phase one — prepublication snapshot v2026-11-02-02

This is the frozen prepublication evidence snapshot for v2026-11-02-02, not a deployment or final-release acceptance receipt. Ordinary CLI and Check observation are disabled. Only newly staged embedded service argv with authenticated startup operation/epoch includes `-dns-observe-service`; existing service args/processes are not edited. This release includes an authenticated DNS stream CachedConn ownership patch to sing-box v1.14.3 (no SDK version upgrade), as well as release metadata. Final-release native, CI, actual public downloads/content audit and isolated version execution remain PENDING here; later results belong in separately identity-bound receipts, not amendments to this snapshot. This does not prohibit subsequently authorized publication, and publication does not install, update the helper, restart a VPN or attempt a privileged TUN probe.

`dns_schema:1` is independent of records/startup. Core collects same-decoded-instance policy and successfully constructed HTTPS factories, marks LOADED after Start, and emits the most recent 64 actual Exchange/ExchangeAsync completions. Runtime JSON digest must match the compiled binding. Sending is an owned one-second worker with 500ms transport deadline, no event goroutines/backlog. Errors are not propagated to forwarding. Public data excludes DNS names/clients/answers/raw errors and arbitrary host/path/config strings. Only fixed safe endpoint/SNI projections are exposed; default port 0 means NOT PROJECTED, not port zero observed on wire. Factory endpoint port is configured rather than independently measured. A successful HTTPS completion plus STRICT_CONFIGURED is not a new TLS handshake or HTTP status observation.

GET `/api/v1/dns-runtime` requires the existing console session, Host/custom same-origin/FetchMetadata checks and post-read session validation. Discovery has no snapshot; bound reads require instance_id/generation/manifest_id and never fall back to latest. Helper keeps an independent copied launch binding, authenticated with the existing launchd/kernel UID/start/full-argv/path composite before/after push; UID0 alone is insufficient. Finished startup does not expire this copied binding. Startup lifecycle replacement/stop invalidates it. Helper restart does not adopt disk latest. Reads use cached memory only and report age/STALE after 2.5s. External lifecycle/registration changes without a subsequent push are detected at authentication of the next push; cached read is explicitly not ongoing liveness/registration attestation.

## Deliberate scope reductions and remaining acceptance gaps

This is NOT a full query/capture/cache ledger. Capture/cache/coalescing/HTTP status/fresh TLS/actual leaf certificate/concrete detour/Router-query join remain NOT_OBSERVED. Actual HTTPS completions and httptrace GotConn acquisition counts are the observed transport scope, not fresh handshakes or certificate readback. Tags, arbitrary SNI/hosts and URL paths are reduced to fixed safe projections to prevent secret leakage. Configured detour is CONFIGURED_ONLY. Accepted Router-return hook is not added.

New APIs do not exist at baseline: baseline compile failures are NOT business RED. Collector used a compiling empty completion seam with an observed expected business RED and GREEN. Subsequent integration tests are test-after; they are not blanket TDD. Private Unix+ServeHTTP tests simulate root/kernel authority (UNIT-SIMULATED) while exercising actual framing, helper cache and authenticated HTTP. Native Darwin composite verifier remains inherited and existing tests retained; this candidate is not production peer/TUN evidence.

Reporter source identity comes from the protected registration, never the staged path hash. Its input must be the exact registered `service/config.yaml`, with root-owned 0700 snapshot root and 0600 regular config; helper independently checks the captured snapshot inode and exact process argv. A peer PID/start/argv rejection does not revoke another run; independently observed registration failure compare-invalidates the captured binding+epoch only, including failure after body read. Publication retains its target fence.

Admission requires retained events to survive byte-for-byte except an oldest prefix justified by a full 64-event ring, monotonic dropped count and GAP. Without GAP sequence must start at one and be contiguous; invalid completions may consume sequence with explicit GAP but do not invent dropped counts. Revision is a per-Snapshot ordinal (missed sends may skip), bounded above by producer elapsed nanoseconds and, at admission, the helper's monotonic elapsed time since pre-launch binding. This rejects future/max revisions without guessing `prev+1`; this is a declared protocol bound, not continuous liveness. Saturation requires GAP.

Successor regression evidence includes distinct source/stage files → actual reporter → private Unix helper → authenticated ServeHTTP discovery/bound read, simulated wrong root PID/start/argv followed by a legitimate push, lifecycle failure/publication fences, collector-enabled actual TLS/auth recovery and blocked cancellation, real constructor sync/async TLS/unreachable/cancel, and fixed-schema maximal 4-transport/64-event frames. Root/kernel ownership remains UNIT-SIMULATED. Baseline business RED is retained separately; compile errors, unsupported wrapper flags and fixture cleanup failures are never labeled RED. The cold-build benchmark shares an exact five-asset/once contract with a normal bounded test; benchmark timing remains NOT_RUN because the official wrapper rejects benchmark flags.

Remaining gaps: independent registration-change invalidation outside helper lifecycle/push, UDP-specific new evidence projection, broader slow sender adversarial matrices, browser DOM execution, production root helper/TUN acceptance. Old-helper errors map to UNAVAILABLE rather than positively identifying UNSUPPORTED. No native green gate waives independent review or authorizes deployment. Ordinary update replaces only the user program, not the root helper; the helper stages the service core from its own executable. New production observation therefore requires the user to perform the existing full-install/system-authorization helper update and explicitly reconnect later; publication performs neither. This is not a Google/site recovery claim. See [release scope and pending gates](releases/v2026-11-02-02.md). The earlier local-candidate wording in the unchanged stream-fix implementation document records its pre-release implementation scope; this release snapshot governs current publication metadata without granting installation authority.
