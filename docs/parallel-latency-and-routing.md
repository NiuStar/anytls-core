# 并发节点延迟与分流调查 v1

## A. 已确认的测速问题与批准实现范围

前端 startProbes 对每节点串行 await；认证 dispatcher 对所有 POST 持 actionMu 到网络探测收尾。只把前端 Promise.all 会变 ACTION_BUSY，不构成并发。

实现：保留现有 POST /nodes/probe 请求/响应与认证、Host/Origin/CSRF/If-Match、固定 HTTPS204目标及双层TLS。该只读探测在认证后专门分派，独立最多8个实际网络探测名额（每webConsole共享，TCP/HTTPS共用），不占用配置/服务动作锁等待网络。配置捕获与解析在 actionMu 保护的短阶段，网络期间释放。网络结束后必须重新 TryLock(actionMu)：占锁时返回409 ACTION_BUSY，不发布测速结果；取锁成功后，在锁内完成配置重读与ETag冲突检查、请求取消／期限复核及受控响应写入，再释放锁。所有成功、错误、取消和收尾竞争路径均释放该请求的探测名额。回归必须持住网络返回前的请求，另行占住actionMu后放行，断言409、无latency_ms／无成功样本，释放动作锁后新请求可成功，证明无名额泄漏。动作锁正在使用时保持ACTION_BUSY，名额耗尽返回429 PROBE_BUSY；拒绝请求不做网络。不增加未限队列，不放松其他mutate锁。每次请求含配置etag复核，不写配置、不select/reload/start。

前端最多8个worker取待测节点，请求逐个完成即更新。所有已排队节点显示等待，活动显示测试中。共享取消代次+全体AbortController；取消/会话/配置变化中止全部活动且不再派后续，迟到不回填。保留busy互斥，finally按代次收尾，不让旧批释放新批状态。单节点网络8秒上限不变；SDK同步构建/Close仍非OS硬期限。并发消除串行总和，不承诺慢节点秒完。

成功显示Math.round(ms)整数，正常非负；原API保留float兼容。颜色依据显示整数：<200绿色、200–499琥珀、>=500红色，失败/超时红色，未测试/取消灰色，测试中蓝色。文本同时表达状态不只靠颜色，风险文字保留。错误不得显示假0ms。保留布局、凭据脱敏、etags与TLS。

验证：同测试旧码RED/新码GREEN；完整认证路由并行进入seam达到>=2且<=8、超限拒绝、占锁拒绝、mutation网络期间可取得锁、取消释放名额、配置变化不发布。Chromium1440/390：持住活动请求证明并发、上限、取消无后继/迟到、不同延迟整数与颜色、失败不显示0、无JS错误。原生Mac full/vet/build与精确双审后才能发布。

## B. DIRECT分流

当前仅调查，未授权凭猜测改路由。必须分别检查规则编译保序、组解析DIRECT、DNS反向映射/域名识别、IP匹配解析与TUN物理出口；实际用户根因未确认。优先合成真实mixed proxy请求证明DIRECT/代理分支的目标连接与AnyTLS对端计数，不用纯map断言冒充数据面行为；TUN正式复现另有权限边界。调查结论后添加最小修复合同及独立规格审查，不同时改TLS/DNS策略和网络栈。
